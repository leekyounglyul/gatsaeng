# 주휴수당·주급 계산기 v1 · 제작 인계

상태: 제작·자동 검증 완료, 시스템 렌더 → 자동 리스크·CD → PM 결재 대상. 외부 배포·CD 점수·리스크 통과를 임의로 완료 처리하지 않았다. 비용 0원.

## 파일

- `index.html`: 배포 원본. CSS·계산·UI JavaScript 내장, 이 파일만으로 계산 가능. Pretendard 고정 버전 무료 CDN 요청 외 서비스 호출 없음. CDN 장애 시 시스템 sans-serif 대체.
- `calculator.js`, `app.js`: 검증·유지보수용 원본. 수정 시 index.html의 대응 인라인 스크립트에도 반영하고 검증할 것.
- `verify.cjs`: Node 내장 모듈만 쓰는 재현 검증. `node verify.cjs`로 실행.
- `docs/validation.md`: 계산 25건과 DOM 대역 검증표.
- `docs/mobile-360.html`, `docs/mobile-390.html`: 자동 렌더 입력. 표준 20시간·개근·범위 확인 사례를 미리 선택한 전체 길이 화면. 배포 대상 아님.
- `docs/references/weekly-pay.capture.txt`: 공식 모의계산·공식 안내·민간 도구 페이지 3개 캡처 요청. 시스템이 `weekly-pay-captures/`에 PNG 생성.

## 사용 방법

시급 → 주 소정근로시간 → 평균시간 → 개근·범위 선택. 입력 변경 즉시 갱신되며 계산 버튼으로도 실행한다. 30분은 0.5시간, 시간 소수 둘째 자리까지. 시급 1~1,000,000원 정수는 제품 입력 상한이지 법적 상한이 아니다. 입력은 URL·스토리지·서버로 보내지 않는다. 결과 공유 버튼은 사용자 클릭 시에만 입력 요약을 OS 공유창에 전달한다. 공유 실패·미지원은 복사, 클립보드 실패는 선택 가능한 textarea로 연결된다. 링크만 복사는 입력값 없이 고정 도구 주소만 복사한다.

2026년 기준·최저시급 10,320원만 제공. 2027 숫자 추측 없음. 시급 수정은 가정 계산이며 법령 연도 갱신이 아님. 평균과 이번 주 소정시간이 다르면 변동 일정으로 취급해 금액을 숨긴다. 미개근은 수당 0원만 표시하고 실제 근로시간이 없어 주급을 숨긴다. 다음 주 근무 여부를 일률적 필수 조건으로 추가하지 않았다.

## 디자인·레퍼런스 적용

공용 `products/content/brand/gatsaeng/`의 최신 가이드·플레이북과 기존 `products/brand/`의 기존 3색·Pretendard 원칙을 확인했다. 공용 v2는 아직 검수 대기 표기라 제안 전체를 승인본으로 간주하지 않고 기존 3색·서체를 유지했다. 요약 박스·단계 카드·팁·주의 부품을 적용했다. 공식 모의계산의 조건 구분을 유지하면서 입력과 결과를 한 화면 두 열(모바일 한 열)로 정리했다. 판매·방문 순위 우위는 확인 불가. 타사 문구·화면을 복제하지 않았다.

CD 비교 시 위 캡처 PNG와 index.html 렌더를 나란히 확인한다. 360px 렌더는 본문·입력·오류·버튼·출처의 가로 잘림을 확인하고, 390px와 함께 실제 글꼴 로딩을 확인한다. 실제 화면을 보지 않은 상태에서 시각 검수 통과로 표시하지 않는다. 캡처 실패 시 공식 페이지 중 확보 가능한 화면으로 비교한다.

## 검증·남은 확인

계산 25건, 조건 변경 시 이전 금액 제거, 공유 미지원·실패/취소, 자동 복사 실패의 직접 복사, 링크 복사, 오류 aria-invalid를 Node·DOM 대역으로 검증했다. 실제 Chrome 실행은 환경 지침에 따라 하지 않았다. 360px CSS는 단일 열·좌우20px·최소48px 조작부·고정 최소폭 없음으로 작성했다. 실제 모바일 화면·폰트·OS 공유창·키보드 포커스는 시스템 렌더/자동 검수에서 확인 필요. 현재 확인된 계산 결함 없음. 렌더 전 CD85나 브라우저 실사용 통과를 주장하지 않는다.

출시 순서: 리스크(지원범위·법령·개인정보·광고코드 없음) → 실제 PNG CD85 이상 → PM 결재 → 시스템 배포. PM은 index.html을 아래 URL에 배포한 뒤 계산 가능 여부를 확인하고 실제 공개일부터 14일 후 평가한다. 분석 SDK가 없어 방문·재방문 지표는 현재 확인 불가다.

예정 URL: https://leekyounglyul.github.io/gatsaeng/weekly-holiday-pay/

이미지 압축 도구·기존 연차 도구 파일과 CTA는 수정하지 않았다. 광고·분석 SDK·계정·서버·DB·유료 API 없음. 추후 연간 기준 갱신 시 index와 모바일 렌더본을 같은 원본에서 생성하는 작은 빌드 스크립트로 동기화하면 반복 작업을 줄일 수 있다.


## 2026-10-16 CD 재작업 인계

- 기존 360·390 PNG를 직접 열어 우측 잘림을 확인했다. 시스템 `app/server/artifacts.ts`는 `--window-size`로만 크기를 지정하고 viewport 수치를 기록하지 않는다. 기존 PNG에는 측정값이 없어 실제 viewport와 PNG 폭의 일치 여부는 확인 불가다. Chrome 최소 창 폭에 따른 캡처 잘림 가능성과 원본의 자동 최소폭 위험을 함께 처리했다.
- 원본 수정: 데스크톱 그리드 `repeat(2,minmax(0,1fr))`, 결과 aside·하위 요소 `min-width:0`, 버튼 줄바꿈·최소폭, 결과 행의 축소 가능 폭을 명시. `overflow:hidden`으로 가리지 않는다. 계산 산식·조건·반올림은 변경하지 않았다.
- 초기 개근/범위가 모두 모름이면 “개근 여부와 계산 범위, 두 항목을 모두 선택” 안내를 표시한다.
- `node sync-preview.cjs` → `node verify.cjs` 순서로 실행한다. 배포 원본에서 검증 JS와 렌더 입력을 생성하므로 코드가 어긋나면 검증이 실패한다.
- 새 렌더 입력: `docs/mobile-360-initial.html`, `docs/mobile-360.html`(정상), `docs/mobile-390-initial.html`, `docs/mobile-390.html`(정상). 각각 시스템이 같은 이름의 PNG를 재생성한다. 과거 PNG는 이번 수정의 증거로 사용하지 않는다.
- 렌더는 배포 HTML 전체를 변경 없이 srcdoc에 넣고 iframe 내부 viewport만 360·390px로 고정한다. 결과 상태는 부모가 개근·범위를 예로 선택하고 submit한다. 원본 해시는 `docs/preview-source.json`에 기록한다. 공개 index.html에는 iframe/진단 코드가 없다.
- 새 PNG 상단 진단에서 **목표 폭=실제 폭=문서 폭, 가로폭 통과**를 확인한다. 외부 viewport는 별도 표기되어 PNG 폭과 브라우저 창 폭이 다른지도 판별할 수 있다. 측정 문구가 그대로 남거나 폭이 다르면 통과 처리하지 않는다.
- CD는 초기 두 안내·미표시 금액, 정상 41,280원·247,680원, 우측 공유 버튼·본문·출처·폰트 및 수평 잘림을 4개 PNG에서 확인한다. 시스템 렌더는 업무 종료 후 실행되므로 이번 작업에서 새 PNG 확인 완료 또는 CD85를 주장하지 않는다.
- 고용노동부 공식 최저시급·표준 산식·평균시간 적용 상담을 2026-10-16 다시 확인했다. 2027 수치는 추가하지 않았다. 법적 범위와 공유 경로를 유지했으나 최종 리스크·CD·PM 자동 검수 대상이다.

남은 작업은 시스템의 4개 신규 PNG 렌더 확인, CD 재채점, PM 결재와 자동 배포다. 제작상 추가 비용 없음. 이 수정은 이미지 압축 도구와 기존 연차 도구 CTA를 건드리지 않는다.
